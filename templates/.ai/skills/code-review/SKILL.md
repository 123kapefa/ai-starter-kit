# Code review

## Когда использовать
- после реализации фичи или фикса;
- перед commit или PR;
- когда нужно независимое мнение по diff.

## Процесс
1. Прочитать задачу и diff.
2. Проверить поведение, контракты и возможные регрессии.
3. Проверить правила проекта, тесты и безопасность.
4. Вернуть замечания с приоритетом и ссылкой на место в коде.

## Границы
По умолчанию read-only: ревьюер сообщает проблемы, а не исправляет их сам.

## Связано
Субагент `code-reviewer` · правило `testing`
