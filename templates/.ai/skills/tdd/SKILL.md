# TDD

## Главное правило
До теста нужно договориться о публичной проверяемой границе — seam. Тест должен проверять поведение через неё, а не детали внутренней реализации.

## Когда подходит
Для самостоятельной логики с понятным ожидаемым поведением.

## Когда не подходит
Для простой склейки, конфигурации или изменений без независимого поведения. Не нужно создавать тесты на воображаемые требования.

## Связано
`implement` · `module-design` · правило `testing`
