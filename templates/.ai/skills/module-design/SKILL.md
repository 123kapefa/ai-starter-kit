# Module design

## Когда использовать
При новом значимом компоненте, неясном владении данными или слишком связанных частях существующего кода.

## Главный принцип
У каждого модуля должна быть ясная ответственность и seam — граница, через которую его можно использовать и тестировать.

## Результат
Схема ролей модулей, интерфейсы, зависимости и решения, которые при необходимости попадают в ADR.
