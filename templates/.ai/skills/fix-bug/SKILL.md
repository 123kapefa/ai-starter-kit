# Fix bug

## Когда использовать
- падение приложения или теста;
- неправильные данные или UI;
- endpoint возвращает неожиданный ответ;
- известен симптом, но не причина.

## Первое условие
Короткий воспроизводимый feedback loop — тест, запрос, команда или сценарий, который быстро показывает проблему. Нет воспроизведения — сначала добыть его, не чинить по догадке.

## Процесс
1. Воспроизвести проблему.
2. Зафиксировать expected и actual behavior.
3. Собрать факты и сузить возможную причину.
4. Сформулировать гипотезу и проверить её.
5. Внести минимальный фикс.
6. Повторить исходный сценарий; добавить regression-тест, если это уместно.

## Границы
Не начинать исправление только по догадке. Не превращать фикс в перепроектирование области без отдельного решения.

## Связано
`implement` · `code-review` · субагент `debugger`
