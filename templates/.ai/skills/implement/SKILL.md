# Implement

## Порядок
1. Понять границы задачи.
2. Выбрать тестируемый seam.
3. При уместности применить `tdd`.
4. Запустить узкие и полные проверки.
5. Выполнить `code-review`.
6. Подготовить итог.

## Перед началом
Проверить ветку, правила репозитория, статус рабочей папки и ожидаемый способ доставки изменений.

## Границы
Не перепроектирует согласованный план. Нет согласованной задачи или спеки — сначала `clarify` / `spec`.

## Связано
`tdd` · `code-review` · правило `git-workflow`
