# Feature

## Когда использовать
- новая пользовательская возможность;
- новый API endpoint;
- новый frontend-flow;
- согласованное изменение frontend и backend.

## Процесс
1. Прочитать `AGENTS.md` и затронутый контекст.
2. Определить требования, области изменения и риски.
3. Показать короткий план.
4. Сборку вести по скилу `implement` (небольшие проверяемые шаги).
5. Проверку — по скилу `code-review`.
6. Проверить API-контракт и документацию.

## Границы
Владеет требованиями, планом и контролем контракта — сам цикл сборки не описывает (это `implement`). Для уже существующей ошибки — `fix-bug`.

## Связано
`implement` · `code-review` · `spec`
